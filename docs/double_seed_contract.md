# 双种子战斗契约（v1）

## 目标

同一个名字无论被放入第几队、位于队伍第几行，均须得到完全相同的八项基础属性。与此同时，改变完整名单的相对顺序必须改变整局对战的伪随机过程，从而允许行动先后、目标选择、伤害波动、事件流和最终胜负随顺序发生变化。

## 角色身份种子

对每一个名称，先执行以下规范化：去除首尾空白、统一换行，并做 Unicode NFC 规范化；大小写与名称内部空格保留，因此 `Alice` 与 `alice` 是不同名字。随后使用 UTF-8 FNV-1a 32 位哈希计算：

```text
identitySeed = FNV1a32("namerena:v1:identity\0" + canonicalName)
```

最大生命、攻击、防御、速度、敏捷、魔法、抗性、智力并不从全局对局随机数中抽取，而是各自从 `identitySeed` 和固定属性盐派生。因而属性只取决于名称本身。

## 对局顺序种子

对局先按输入的空行解析队伍，再以原有队伍顺序、队内顺序和规范化名字重构完整文本。使用 UTF-8 FNV-1a 32 位哈希计算：

```text
matchSeed = FNV1a32("namerena:v1:match\0" + orderedTeamText)
```

`matchSeed` 初始化唯一的 xorshift32 伪随机发生器。该发生器只供目标选择、伤害浮动、暴击判定及其他对局事件使用；角色属性生成不得消费它。

| 项目 | 取决于 | 改变位置是否变化 |
|---|---|---|
| 角色基础属性 | 规范化名字的身份种子 | 否 |
| 特殊名字预设 | 特殊名字代码 | 否 |
| 行动并列时的先后 | 基础速度、敏捷、输入索引 | 可能 |
| 目标选择与伤害浮动 | 完整名单顺序的对局种子 | 是 |
| 战斗事件流与结果 | 上述对局状态 | 可能 |

## 可移植性

所有哈希与随机计算均限定在无符号 32 位整数范围内。未来 C++/WASM 核心须使用 `std::uint32_t`、UTF-8 编码、相同 FNV-1a 常量与 xorshift32 移位顺序。React/TypeScript 层仅展示核心返回的角色档案与事件流，不重算战斗结果。
